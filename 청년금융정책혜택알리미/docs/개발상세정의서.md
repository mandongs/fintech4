# 청년 금융정책 혜택 알리미 개발상세정의서

## 1. 문서 목적

본 문서는 `청년 금융정책 혜택 알리미` 서비스의 MVP 개발 기준을 정의한다. 현재 저장소 구조와 구현된 기능을 기준으로 프론트엔드, 백엔드, 데이터, API, 배치, 화면 흐름을 정리한다.

## 2. 시스템 개요

- 프론트엔드
  - React 18
  - TypeScript
  - Vite
  - React Router
  - TanStack Query
  - styled-components
- 백엔드
  - FastAPI
  - SQLAlchemy
  - SQLite
- 기타
  - 배치 스케줄러 기반 데이터 수집/알림 처리
  - AI 상담 API 연동 구조

## 4. 서비스 아키텍처

### 4.1 프론트엔드

- Vite 개발 서버는 `5173` 포트를 사용한다.
- `/api` 요청은 `http://localhost:8001` 백엔드로 프록시된다.
- 로그인 상태가 아니면 보호 페이지 접근 시 `/login`으로 이동한다.
- 주요 화면 라우트
  - `/login`
  - `/register`
  - `/recommend`
  - `/policies/:id`
  - `/alerts`
  - `/financial`
  - `/chat`
  - `/profile`

### 4.2 백엔드

- FastAPI 앱 시작 시 DB 테이블 생성
- 앱 시작 시 배치 스케줄러 등록
- CORS 허용 대상
  - `http://localhost:5173`
  - `http://localhost:3000`
- 헬스체크
  - `GET /health`

## 5. 핵심 기능 상세

### 5.1 인증

- 기능
  - 이메일 회원가입
  - 로그인
  - 리프레시 토큰 재발급
- 처리 방식
  - 비밀번호 해시 저장
  - JWT Access Token, Refresh Token 발급
- 예외 처리
  - 중복 이메일 등록 시 `409`
  - 로그인 실패 또는 유효하지 않은 토큰일 경우 `401`

### 5.2 사용자 프로필

- 입력 항목
  - `birth_date`
  - `annual_income`
  - `region_name`
  - `region_code`
  - `marriage_status`
  - `employment_type`
  - `job_code`
  - `school_code`
- 처리 로직
  - 사용자의 기존 프로필이 없으면 신규 생성
  - 입력값 저장 후 `categorize_persona`로 페르소나 산출
- 의존성
  - 정책/금융 추천은 `birth_date` 포함 프로필이 있어야 정상 동작

### 5.3 정책 추천

- 데이터 소스
  - `policies` 테이블
- 처리 로직
  - 사용자 프로필과 전체 정책 데이터를 비교
  - `filter_and_rank_policies`로 상위 정책 선별
  - 정책별 `match_score`, `days_left` 계산
- 프론트 표시 정보
  - 정책명
  - 대분류/소분류
  - 설명 요약
  - 주관기관
  - 신청 URL
  - 신청 마감일
  - 매칭 점수

### 5.4 정책 상세

- 조회 대상
  - 정책 기본정보
  - 지원 내용
  - 신청 방법
  - 참고 링크
  - 연령/소득 조건
  - 신청 기간 및 D-day
- 추가 처리
  - 상세 조회 시 `view_count` 증가

### 5.5 금융상품 추천

- 데이터 소스
  - `financial_products` 테이블
- 처리 로직
  - 프로필 기반 상품 추천
  - `product_type` 필터 지원
  - `recommend_financial_products`에서 추천 사유 생성
- 상품 유형
  - `saving`
  - `deposit`
  - `rent`
  - `mortgage`
  - `credit`

### 5.6 북마크 및 알림

- 북마크
  - 정책 관심 등록/해제
  - 북마크 생성일 기준 내림차순 정렬
- 알림
  - `GET /api/alerts?days=30` 형태로 마감 임박 정책 조회
  - 화면에서는 특히 7일 이내 정책을 강조 표시
- 상태값
  - D-day 계산 결과에 따라 상시, 마감, D-DAY, D-n 표시

### 5.7 AI 상담

- 입력값
  - `question`
  - 최근 대화 이력 `history`
- 컨텍스트 구성
  - 프로필이 있으면 추천 상위 정책 10건을 문맥으로 사용
  - 프로필이 없으면 기본 정책 10건을 사용
- 출력값
  - `answer`

## 6. 화면 정의

### 6.1 로그인 페이지

- 이메일/비밀번호 입력

- 신규 계정 생성

- 프로필 등록 및 수정
- 사용자 페르소나 배지 표시
- 추천 기능의 선행 입력 화면 역할

### 6.4 추천 페이지

- 맞춤 정책 카드 목록 표시
- 정책별 카테고리, 기관, D-day, 매칭률 노출
- 외부 신청 링크 이동
- 북마크 추가

### 6.5 정책 상세 페이지

- 정책 상세 정보 조회
- 신청 링크 이동
- 북마크 추가

### 6.6 알림 페이지

- 마감 임박 정책 목록
- 북마크 목록
- 북마크 삭제

### 6.7 금융상품 페이지

- 상품 유형 탭 필터
- 상품명, 금융사, 한도, 추천 이유 표시

### 6.8 AI 상담 페이지

- 대화형 질문/응답 UI
- 빠른 질문 버튼 제공
- Markdown 응답 렌더링

## 7. API 정의

### 7.1 Auth

| Method | Path | 설명 |
|---|---|---|
| POST | `/api/auth/register` | 회원가입 및 토큰 발급 |
| POST | `/api/auth/login` | 로그인 및 토큰 발급 |
| POST | `/api/auth/refresh` | Access Token 재발급 |

### 7.2 Profile

| Method | Path | 설명 |
|---|---|---|
| GET | `/api/profile` | 내 프로필 조회 |
| POST | `/api/profile` | 프로필 생성 또는 수정 |

### 7.3 Recommend

| Method | Path | 설명 |
|---|---|---|
| GET | `/api/recommend/policies` | 맞춤 정책 추천 |
| GET | `/api/recommend/financial` | 맞춤 금융상품 추천 |

#### Query Parameter

- `/api/recommend/policies`
  - `top_n`: 기본 20, 최대 50
- `/api/recommend/financial`
  - `product_type`: 상품 유형 필터
  - `top_n`: 기본 10, 최대 30

### 7.4 Policy

| Method | Path | 설명 |
|---|---|---|
| GET | `/api/policies` | 정책 목록/검색/필터 |
| GET | `/api/policies/{policy_id}` | 정책 상세 |

#### Query Parameter

- `category`
- `keyword`
- `region_code`
- `page`
- `size`

### 7.5 Alert/Bookmark

| Method | Path | 설명 |
|---|---|---|
| GET | `/api/alerts` | 마감 임박 정책 조회 |
| GET | `/api/bookmarks` | 북마크 목록 조회 |
| POST | `/api/bookmarks/{policy_id}` | 북마크 등록 |
| DELETE | `/api/bookmarks/{policy_id}` | 북마크 삭제 |

### 7.6 Chat

| Method | Path | 설명 |
|---|---|---|
| POST | `/api/chat` | AI 상담 응답 생성 |

## 8. 데이터 모델 요약

### 8.1 users

- 사용자 계정 정보
- 주요 컬럼: `id`, `email`, `hashed_password`, `created_at`

### 8.2 user_profiles

- 사용자 개인 조건 정보
- 주요 컬럼: `birth_date`, `annual_income`, `region_code`, `marriage_status`, `job_code`, `school_code`, `employment_type`, `persona`

### 8.3 policies

- 청년정책 마스터 데이터
- 주요 컬럼: `id`, `name`, `category_main`, `category_sub`, `description`, `support_content`, `apply_method`, `apply_url`, `min_age`, `max_age`, `earn_min`, `earn_max`, `region_codes`, `apply_start`, `apply_end`

### 8.4 financial_products

- 금융상품 마스터 데이터
- 주요 컬럼: `company_name`, `product_name`, `product_type`, `join_method`, `is_youth_product`, `max_limit`, `dcls_month`

### 8.5 user_bookmarks

- 사용자 관심 정책 저장 데이터
- 주요 컬럼: `user_id`, `policy_id`, `notify_enabled`, `created_at`

### 8.6 notification_logs

- 알림 발송 이력 저장용 데이터
- 주요 컬럼: `user_id`, `policy_id`, `days_left`, `sent_at`

## 9. 배치 및 운영 기능

- 배치 목적
  - 청년정책 데이터 수집
  - 금융상품 데이터 수집

## 10. 예외 및 유의사항

- 추천 기능은 프로필, 특히 `birth_date`가 없으면 `400` 오류를 반환한다.
- 외부 신청 링크는 `http`로 시작하는 경우에만 프론트에서 버튼을 노출한다.
- 현재 DB는 SQLite 기반이므로 운영 환경 확장 시 RDBMS 전환 검토가 필요하다.
- 문자 인코딩이 일부 파일에서 깨져 보일 수 있으므로 문서/소스 저장 시 UTF-8 통일이 필요하다.

## 11. 비기능 요구사항

- 반응형 UI 지원
- 주요 조회 화면은 사용자 대기 시간을 줄이기 위해 비동기 데이터 패칭 사용
- 인증이 필요한 API는 토큰 기반 보호
- 유지보수를 위해 도메인 단위 폴더 구조 유지
